# MiniMax H3 Max R2V 研究版架构

## 目标与基线

本仓库的本质目标不是改造生产后端，而是让固定 Master 极简前端拥有一个独立、可研究的新后端。前端基线与 `video-maker` 之前的算法基线固定为 `github-xy-plus/Master@043166b13f21fdf715390b964e843be2c010ddcf`；源仓库的后续变化不会隐式改变本链路。

技术边界与质量判断严格分开：服务端负责让请求安全、可归属、可执行和可追踪，但不判断生成内容“够不够好”。供应商拒绝、网络错误、命令失败和文件缺失是自然执行错误；结构化模型节点只校验 closed JSON 形状、字段类型及输入绑定，不二次验证索引、替换、音色、台词或提示词语义，也不因此失败或重试。

## 数据流与屏障

项目级公共输入依次产生：

1. 原视频精确解码帧轴、4 fps 分析帧与规范音频；规范音频再经 vocal-separation 节点（本地 audio-separator CLI 子进程 + UVR-MDX-NET-Inst_HQ_3 模型，独立 venv 不入生产依赖，配置缺失即节点明确报错）分离出非人声伴奏轨 `work/accompaniment.wav`（人声轨仅调试用，不进下游），无音轨源视频该节点同步跳过。
2. 项目级视频字幕擦除（`remove_subtitle` 开关）：MediaKit 异步 `erase-video-subtitle-pro`（固定 `model_version=v5`）或标准版（`MEDIAKIT_VIDEO_ERASE_MODE=pro|standard`）抹掉烧录字幕，产出 `work/source-nosubs.mp4`；分段、抽帧、ASR 等下游全部改用擦除后的文件，失败 fail-closed。submit accepted 即付费：回执（task id、video URL、submit 记录）立即原子落盘 `work/erase-source-subtitles-receipt.json`，节点重跑先读回执——accepted 回执直接 poll/download 复用已付费任务不重复 submit（记 `mediakit_subtitle_erase_receipt_reused`），只有回执任务终态失败（供应商 FAILED）才标记 `provider_failed` 并允许重新 submit（记 `mediakit_subtitle_erase_receipt_reset`），download 落盘后回执标记 `downloaded`，重跑不重复下载；整个节点重试限 3 次（`MEDIAKIT_ERASE_NODE_MAX_ATTEMPTS`），超限抛 `MediaKitEraseRetryExhaustedError` fail-closed（记 `mediakit_erase_retry_exhausted`）。H3 prompt 的 overlay removal 声明保留为双保险。
3. YAMNet 声学分类和 Whisper 台词；自动台词只投影 spoken 行。
3. `ContentDetector(threshold=27)` 的精确镜头边界。
4. 4–10 秒 scene-first 片段计划及逐段 exact-9。
5. 可选 MediaKit 处理，先文本擦除、再图标擦除。
6. 每段 `video-maker` 视觉提示词。
7. 一次项目级台词翻译和一次 `video-maker` 全局原始对象索引；索引同时接收各段 `visual_prompt` 作为回看九帧的防漏清单，像素仍是唯一视觉事实。
8. 后端从 raw stable index 确定性生成 `replacement_set`：`people/entities/scenes` 分别包含本类全部 stable key 并排序；同时生成仅移除这三类记录顶层 `preserve/replaceable` 的模型规划视图，relations 和其他事实不变。
9. 一次项目级 DeepSeek Object Replace v6：读取规划视图、`replacement_set`、全部逐段视觉提示、目标语言与项目级翻译台词、可选用户图及说明，以及当前音色目录；输出绑定 stable key 的 replacement/voice patch，每个非空 replacement 分离 `appearance_description` 与 `target_visual_description`，并逐行输出 `dialogue_voices` 台词说话人归属（人物 stable key 或 null=旁白）。
10. 后端深拷贝完整 raw index 并机械合并 patch，生成项目级增强索引（含独立 `dialogue_voices` 块：逐行绑定豆包音色目录内的 `voice_type`，目录见 `assets/doubao-voices/catalog.json`，注入模型的只是按目标语言过滤的子集）。不再物化本地音色参考音频。
11. 台词音频链（tts20-ark）：翻译完成后立即执行 ark-audio-analysis（付费方舟音频理解，紧随翻译、不等 object-replace），按台词窗口切逐行原音片段，产出语速/语调情绪/停顿/整体语气/性别年龄五字段描述，逐行持久化、按行号+窗口+model 绑定复用；各行语气描述同时按行窗中点归属段窗可选注入 fusion payload（见下文 Fusion 段）；dialogue-delivery-plan（DeepSeek）按窗口预算公式逐行规划 `speech_rate`（基准语速取 `app/doubao_voices.py` 的 `VOICE_BASELINE_RATES` 实测标定值；标定是音色可用性总闸门：未标定音色不进 Object Replace 提示词精选子集、不做默认音色、选音色不选，冻结产物里的未标定绑定消费侧回落默认音色，仍漏到规划的节点明确报错）与 `emotion`/`context_texts`；逐行台词 TTS：豆包语音合成 2.0（`app/doubao_tts.py`，火山 openspeech V3 HTTP 单向接口）用逐行解析的 voice_type（无绑定回退该语种的通用默认音色）带 speech_rate/emotion/context_texts/section_id 串行合成，section_id = uuid5(run_id:voice_type)（每次运行 × 每说话人一个 section，同 section 内跨行语气连贯；已收 finish 后本地落盘失败判死 fail-closed，禁止同 section 重发）；续跑按行复用（行 wav 非空可解码且逐行输入哈希一致才复用，否则重新合成）；装配成整条静音底轨音轨（超窗 atempo 封顶 1.15x、再超按尾差淡出截断，欠窗留停顿），并切出每段 `dialogue-track.wav`；任一环节失败项目 fail-closed。无台词项目跳过分析/规划/合成/装配（vocal-separation 与最终混音不跳过）。
12. 后端以冻结 enhanced index 为唯一身份锚点，把所有实际非空 replacement 确定性映射为 `stable key -> TILE_XX -> row/column`，生成 sheet bundle v4/spec v2 并从 `appearance_description` 编译隔离式提示词；Seedream 每项目调用一次，以空白布局为 Image 1、可选规范化用户图为 Image 2，生成一张 2048×2048 新形象图版，不生成或发送源帧证据。

只有上述公共输入完成并能传给下游，才启动逐段 R2V 准备。所有片段先并行完成 Fusion、最终提示词和静音 @Video 1；随后完成有序参考图、遮罩视频与台词切片的 BytePlus 白名单加白（CreateAsset→GetAsset Active）和 Seedance 硬参数预检，才允许发出 Seedance POST。这些屏障只防止缺文件、供应商参数不合法和半批次付费，不判断模型内容质量。白名单加白失败（GetAsset→Failed）时尚未提交生成、零费用，项目标 failed 不自动重试。

每段分支按以下顺序执行：

```text
h3-max-r2v-prompt Skill
  -> 后端机械附加台词与相对时间窗
  -> 有替换人物或物品的段：静音参考经 fal.ai SAM 一次多目标检测统一深灰块打码（mask-replaceable-objects；未配置 FAL_KEY 不触发）
  -> Seedance 接收静音（或打码）源片段 @Video 1、项目级同序 @Images 和本段台词语音切片 @Audio 1（无台词段不传音频），全部 asset:// 引用
  -> 可选 h3-context-ir：MiniMax 官方 Context IR 提示词优化（冻结后、提交前逐段，见下）
  -> Seedance submit
  -> 使用同一 task ID poll
  -> 立即下载供应商结果
  -> 24 fps 帧预算裁回源片段时长
```

最终按原 segment 顺序统一媒体规格并 concat。成片音轨覆盖规则（均丢弃 H3 自生成音频）：有台词且有伴奏轨时，整条 TTS 台词轨与 `work/accompaniment.wav` 经 ffmpeg sidechaincompress ducking 混音（台词轨作 sidechain key，标定终值与出处见 `app/media.py` `mix_dialogue_with_accompaniment` 注释）后覆盖成片音轨；无台词但有伴奏轨时成片音轨 = 伴奏轨（保留原音效/BGM/环境音）；伴奏缺失（无音轨源视频、存量续跑项目）沿用旧降级分支（台词轨覆盖或静音轨）。

## 上游算法语义

- 分段在每个起点之后的 4–10 秒窗口内优先选择最晚真实镜头边界；没有候选才使用时长切点；不足 4 秒的尾段会回撤前一切点。
- 台词区间只做技术解析，不参与切点选择。跨段台词按各段时间交集切分文本，再转换为段内相对时间。
- exact-9 从原视频完整 PTS/解码序号清单中选取。场景不超过九个时先给每个场景一帧，再用 Hamilton 最大余数法分配剩余名额；稀疏输入确定性重复；超过九个场景时压成九个连续分析槽，但保留完整 source cut timeline。
- MediaKit 的文本擦除先于图标擦除。处理后的全尺寸九帧是两个 `video-maker` 阶段的共同权威输入；送模型时另建半尺寸分析副本。

## 模型合同

`video-maker` 以固定 Master 的既有 Skill 为基线；逐段视觉合同保持不变，项目索引阶段增加防漏清单和精确段身份绑定：

- 逐段阶段用 `VISUAL_PROMPT_SCHEMA` 返回 `{prompt}`，业务层只解包字符串；不设置任意最短长度或内容覆盖门禁。`visual_prompt` 末尾必备"产品呈现"段（按"叙事角色 × 展示手法"双维记录：叙事角色取自被演示的证据/被声称的对象/展示的材质/CTA 落点，展示手法、演示的身体部位与接触方式、镜头配合照原纪律，只写像素可证实的事实，无则逐字写"本段无产品呈现"）；关键镜头变化与产品镜头另追加"作用："前缀的功能归因句，节奏写成"事实→感受"双句——事实与归因显式分离、归因必须锚定已陈述事实，功能归因只进逐段 visual_prompt、不进项目级索引 relations（出处：hypit reference-video/transformations 指南的中文化，见 skill 正文内联标注）。原视频无法提供的信息在全链路（含下游 fusion）一律禁止猜测或编造（2026-09-29 用户决策；此前"猜测增强只发生在下游 fusion"的安排已随 fusion 增强机制一并摘除）。
- 项目索引阶段接收 `phase`、生效的 `generation_config`，以及按 segment/frame 排序的 `segment_index`、`visual_prompt`、`frame_order`、项目内路径、SHA 和全部分析图片；不接收台词或用户素材。`visual_prompt` 只用于逐项提示模型回看对应九帧，不能替代或推翻像素证据。运行时根据本次请求中的正整数段号构造动态 closed Schema，人物、实体、场景和关系的 occurrence 只能引用这组精确段号，不能输出 `0`、未知段号或自行重新编号。输出 closed 结构后由后端机械分配已有项的稳定 ID，原样写入 `work/element_index.json` 和 `state.element_index`。people/entities/scenes/relations 允许为空，不要求必须识别场景或达到任意集合大小；Object Replace 不回写 raw index。

项目级 `object-replace` Skill 固定使用 DeepSeek，每项目只设一个公共逻辑节点，不按 segment 重复；首次自然执行错误仍受下文“每节点最多两个 attempt”边界约束。调用前，后端从 raw stable index 确定性生成 `replacement_set={people,entities,scenes}`，每类包含全部 stable key 并排序；送模型的 `global_element_index` 是深拷贝的规划视图，仅移除这三类记录顶层的 `preserve/replaceable`，relations 和其他字段不变。完整 raw index 始终冻结，并在返回 patch 后作为机械合并基底；Fusion 接收的 enhanced index 因而仍包含完整 raw 事实。

closed JSON Schema（version 与 `OBJECT_REPLACE_OUTPUT_VERSION` 同步，当前 6）由 raw index 中已有 stable key、音色 ID 集合和输入哈希动态生成；patch 字段中的 `replacement` 与人物 `voice_id` 均允许 `null`。每个非空 replacement 包含 `source`、`appearance_description` 和 `target_visual_description`：`appearance_description` 只供 sheet，限定为单个 stable key 的内在可见外观，不能写动作、接触、相对位置、所在场景或其他 stable key；`target_visual_description` 只供 Fusion/H3 承载动作、接触与关系。Skill 自身要求 `replacement_set` 中所有人物、实体和场景输出非空替换，并为人物选择符合特征的音色。同一 stable key 跨图片、分段和 occurrence 使用同一套新设计。用户图只约束用户文字唯一语义对应的一个既有 stable key；其他 key 仍各自使用 `generated_variant`，不得因参考图只指向一个元素而停止替换。人物替换默认保持源人物的性别、年龄段、人种和肤色（v6 人种一致性规则：目标台词语言的典型人种与源人物不一致时以目标语言为准替换为对应人种人物，`dialogue_voices` 音色同步匹配替换后人种与语言；人种/肤色不计入「至少两个可见维度差异」的差异维度，差异须来自发型、脸型、面部标记等），更换身份使人脸或可见身体产生差异；只露出身体局部时，统一改变局部形态、比例、肤色、纹理或标记，不为具体部位写特例；服装保持颜色和风格但改变款式。场景保持类型、用途、布局、色调、构图、机位、镜头运动、焦段和光线，但改成同类不同实例。实体保持功能、动作接口和尺度，但改变材质、颜色、品种、轮廓、结构或造型；动作、接触与相对关系不得回流到图版外观。上述都是模型生成职责；后端只校验结构和输入绑定，不把 replacement 非空、用户目标命中、替换覆盖、关系协同或声音标签语义变成质量门禁。

后端在 patch 结构可读取后深拷贝 raw index 并机械合并：`occurrences`、`preserve`、relations 和原始描述不变，对应记录增加模型给出的 nullable `replacement`，人物增加 nullable `voice`。人物可共用 `voice_id`；后端按稳定人物顺序保留最先出现的最多 3 个不同可用 ID，后续新 ID 稳定降级为 `null`，而不是让项目失败。保留下来的文件依次复制为 `work/voice-references/audio-01.wav` 至 `audio-03.wav` 并写入增强索引。当前仓库附带 30 条 2–5 秒单声道 PCM WAV，但运行时不要求目录恰好 30 条，也不复审年龄、性格等描述是否主观准确；只保留文件可读、媒体可用和供应商最多 3 条参考音频等技术限制。

图版节点不让 Seedream 重新建立身份：sheet bundle v4/spec v2 的 TILE 顺序、位置、stable key、类别和 `appearance_description` 都由后端从 frozen enhanced index 生成并冻结，Seedream 只在每个固定格内画出对应新设计。人物格只包含该人物或可见身体局部，实体格只包含该实体，场景格必须是无人物、动物和可移动实体的空置环境；图版不是源视频画面的重演。Seedream 输入固定为 `Image 1=空白布局`，存在绑定时才追加 `Image 2=规范化用户图`，不生成或发送源帧证据。用户图只可影响 `source=image_1` 的 tile，不得扩散到其他 stable key；这里的 `source=image_1` 是 Object Replace/H3 的用户图角色，后端确定性映射到 Seedream Image 2。图版生成结果只做图片解码、统一尺寸、标签复写和文件/哈希绑定等技术处理；不新增“是否画得像”“是否每格替换成功”之类的本地视觉质量门禁。

- `resume-picsart` 已越过付费屏障，只复用 H3 manifest v9 冻结的每段 `source-muted.mp4`（或 fal.ai SAM 统一深灰打码产物）、`h3_prompt.txt`、台词语音切片、同一张图版和相同顺序的有序图片；它不重跑 raw index、Object Replace、TTS、Seedream 或 Fusion。恢复严格校验版本、路径、哈希、媒体和请求绑定，不把图版画面或 `voice_references` 与 enhanced index 做二次语义复审；素材按白名单账本中 Active 条目直接复用 asset:// 引用，缺失或已清理的按内容 sha256 重新加白。已有且未明确失败的 task ID 只继续 poll/download。

## 重试、证据与付费边界

普通节点每次尝试有独立的 `attempt-N` 证据目录，抛出可重试的自然执行错误后重试：第 2、3 次尝试立即重跑，第 4 次起按 1 分钟基准指数退避（封顶 30 分钟），直到成功。传输类错误（ProviderFailure 非 4xx、TimeoutError、ConnectionError、JSONDecodeError、subprocess 超时、ENOSPC 等，请求未到达不扣费）不限次数；ValueError/MediaError/AssertionError（模型输出已付费但不可用类，每次重跑都重新付费）节点级重跑限 3 次（`NODE_MODEL_OUTPUT_RETRY_MAX_ATTEMPTS`），超限 fail-closed 抛 `NodeModelOutputRetryExhaustedError`（写明节点名与末次错误）等人工介入。续跑或重跑同一节点时 attempt 编号从已有证据目录的最大值继续，失败 attempt 的原始 input/output 不被覆写。DeepSeek 结构化输出的 JSON 解析或合同校验失败时，先在同一个会话内回附错误输出和修正指令让模型重答（最多 3 次修正，全部中间交换记入 provider record 的 `json_repairs`），仍失败才抛回原错误走节点重试；Codex 是一次性子进程，输出校验失败后直接走节点级整体重跑。strict 解析失败时先回退 `strict=False`，容忍字符串值内的裸控制字符；逐段 visual prompt、object-replace 与 fusion 输出的顶层校验容忍模型多输出的额外键（元素级键集同样只拒少键、容忍多键）。可重试集合覆盖供应商/网络错误、subprocess 超时、ffmpeg 非零退出（`CommandError`）、Codex 进程错误（`CodexProcessError`）、磁盘写满（`OSError` ENOSPC，属暂时性故障，清盘后自愈）和瞬时模型输出解析错误；ProviderFailure 的证据记录中含确定性 4xx（除 408/429 外的一切客户端错误，如供应商对损坏上传图返回 400/422）时判定重试无意义，快速失败而不是无限循环；节点执行抛出的 ValueError/MediaError（无论模型输出还是媒体消费校验）与防御残留 AssertionError 走 3 次付费预算重试（见上），让不确定性自愈但不无限扣费，只有 TypeError/KeyError/AttributeError 保持程序 bug 判死语义；审核类拒绝（content policy/moderation 等 marker）同样退避重试而不是判败，同一错误指纹连续失败 5 次起每次记录 `node_moderation_persistent` 显著事件。不可自愈的其余错误仍可失败，但失败时把具体错误码写入 `state.error.code` 供对外映射，不再是笼统的 `pipeline_failed`。fal.ai SAM 统一打码节点连续失败达到阈值后降级为不打码继续（记 `object_mask_degraded`；未配置 `FAL_KEY` 时节点不触发），没有本地检测模型门禁；终剪时整条台词音轨缺失降级为保留拼接视频（记 `dialogue_track_missing_degraded`）。Whisper 返回空 ASR，或 YAMNet 与 ASR 没有可重叠的 spoken 区间时，直接以空台词继续，不因内容为空再跑一次；翻译结果缺行或某行为空时回退对应源文，也不失败或重试。

Seedream 在发出 POST 前原子持久化与 prompt、模型和输入图片哈希绑定的 receipt/claim。已存在成功响应时只物化同一结果；`submission_unknown`/协议错误自动清除本次尝试产物（记 `seedream_receipt_reset`/`seedream_submission_regenerated`）并重提同一冻结请求，内容拒绝（`provider_rejected`）在重提前对 prompt 做一次微小扰动并重新冻结回执。三类可再生 outcome 共用自动重提上限 3 次（`SEEDREAM_REGENERATION_MAX_ATTEMPTS`，每次重提都是新的付费生成），超限 fail-closed（记 `seedream_regeneration_exhausted`，`SeedreamRegenerationExhaustedError` 写明需人工介入，回执与尝试证据保留）。resume 路径上的 rejected/submission_unknown 回执走同一重置重提路径（recovery mode `regenerate`），人工 resume 续跑不受自动预算限制，不再锁死续跑。

Seedance submit、poll、download 是三个节点。每次被允许的 submit 在 POST 前先原子冻结 `submission_started` 回执；取得 `taskId` 后立即写成 accepted 回执，再进入 poll。终局任务失败按 `classify_seedance_error` 分桶：`content_rejected`（输入侧审核拒绝：SensitiveContentDetected/InputText/InputImage/moderation_blocked）/`bad_request`（InvalidParameter.*/PolicyViolation）/`payload_too_large`/`reference_fetch_failed`（引用已是 asset://，不存在换 URL 再试）终局不重投（记 `seedance_terminal_failure_no_resubmit`）；`output_content_rejected`（输出侧审核 Output*SensitiveContentDetected——审核的是本次生成画面/音频，换 seed 重投可能过审，2026-09-30 用户确认没输出不扣费后放开）、其余终局失败与 hang（超过 `SEEDANCE_TASK_HANG_LIMIT_S` 仍非终态）换新 run identity 重投同一冻结请求（asset:// 引用随白名单持续有效），付费重投硬上限 `SEEDANCE_MAX_PAID_RESUBMITS=3` 次，超限标 failed（code `seedance_resubmit_cap_exceeded`），逐次记录 `seedance_terminal_failure_resubmit`。429/5xx/timeout 只续查 poll，不重新付费提交；取得 ID 后，poll 和 download 的失败只重试自身，不能回到 submit。submit 自身的 `submission_unknown`（无 task ID）仍需人工对账后才允许 resume 再 POST；进程重启时，没有 accepted 提交日志佐证的 `submission_started` 回执自动降级为 rejected，满足续跑门禁的项目在服务启动时自动排队续跑（记 `auto_resumed_after_restart`），不满足的保持 failed 并在日志写明人工对账指引（记 `auto_resume_after_restart_blocked`）。项目终态（succeeded 全段下载完成或 failed）best-effort DeleteAsset 本项目全部白名单素材，失败仅记日志不阻塞。

供应商适配器把业务值与 provider record 分离。业务对象、raw/enhanced 索引和下游 prompt 不携带原始供应商请求；原始记录只进入对应 attempt 日志。二进制响应作为媒体证据保存，JSON 只记录状态、headers、长度和摘要，不把二进制误解码成文本。

日志失败只能写进进程 stderr，不能改变业务结果。日志目录逐层为 `0700`，文件为 `0600`，默认永久保留并由人工删除。

## 主机与访问边界

- 登录和前端 API 使用 Bearer 鉴权；供应商素材 URL 只使用独立高熵、项目绑定且限时的 token。
- 上传磁盘名由服务端决定，客户端 filename 只作显示元数据；视频和替换图分别执行字节上限。
- 外链视频每次跳转都重新做 URL、DNS 与全局 IP 校验，实际连接钉扎到已批准 IP，同时保留 Host/SNI；下载流同时受 Content-Length 和实际累计字节限制。
- 项目文件路由是逻辑名 allowlist，不接受任意项目相对路径。签名素材在注册和读取时都重新验证真实路径属于对应项目，`GET` 与供应商预检使用的 `HEAD` 共用同一验证路径。
- 状态只使用 `queued/running/succeeded/failed`。纯文件存储、后台任务和内存 token 表限定单实例；同一数据目录不允许重叠进程。
