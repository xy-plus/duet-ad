# H3 Max R2V Prompt

只生成可直接提交给视频模型的一段提示词，不解释过程。传输格式以本次调用注入的 JSON Schema 为唯一权威：逐字回填固定的 `schema`、`version`、`input_sha256` 和 `segment_index`，把完整提示词放入 `prompt`；不得增删字段，不输出 Markdown。

输出语言：后端会在整行 `BEGIN AUTHORITATIVE OBJECT REPLACEMENT AND VOICE PLAN` 处拆分你的 `prompt`，该行之前的可见主体（动作描述、替换描述等你输出的全部内容）一律用中文撰写；该行起的权威计划块由后端机械附加，其结构、字段和英文措辞完全固定，不属于你的输出，不得翻译、改写或复述其中任何内容。

冻结的 `global_element_index` 是本项目唯一对象身份、替换与人物音色锚点。不得重新识别、重命名、合并或拆分 stable key，不得重新决定替换目标，不得要求读取用户替换说明，也不得根据常识新增替换。逐项读取当前 segment 的 occurrences、replacement、voice、preserve 和 relations。

`replacement_sheet` 是按同一冻结索引生成的项目级单张新形象图版；`h3_reference_images` 给出 H3 图片的有序角色。后端生成的 `stable key -> TILE_XX -> 实际 Image N` 映射是唯一图片引用权威：图版固定为 `Image 1`，用户图按其冻结 `reference_id` 的顺序依次为后续 `Image N`。对 `replacement.source=image_1` 的 stable key，权威块会列出它唯一可用的用户图编号；这些原图是该 key 的外观权威，图版 tile 仅用于定位该 key 和保持跨段映射。不同用户图既不预设为同一商品、同一人物或不同视角，也不得扩散给未绑定 stable key。对 `generated_variant` 的 key，仍只以自身图版 tile 为外观权威，必须忽略全部用户图。多个 stable key 可按冻结计划共享同一组用户图，却仍各自保留身份、occurrences、动作和位置关系，不得合并。同一项目的每个 segment 必须沿用同一张图版和同一套映射，不得重新编号或自行推断图片顺序。

若 `replacement_sheet.h3_image_reference=null`，本次没有图版：`h3_reference_images` 中原图从实际 Image 1 开始排序，`user_reference_images` 明确每个 reference_id 对应的真实槽位。不得虚构空白图版或源对象来凑编号。即使没有任何已选中的用户绑定，已上传原图仍是可见输入；已知 generated_variant key 不因此继承它们的外观。

`authoritative_constraints` 是后端从增强索引和图版 spec 机械编译的本段替换、`stable key -> TILE_XX -> Image N`、关系和人物音色/台词轨权威块，后端会在你的 `prompt` 尾部原样附加。你必须以它规划主体提示；主体中不得出现稳定 ID、TILE、Image N、Audio N 或 BEGIN/END 块，不得另写对象、图片或音色映射，也不得输出与它冲突的要求。后端只校验输出结构和输入绑定，不会二次判断你是否完成这些语义要求；完整表达替换、音色和连续性是本节点自身职责。

后端会在你的 `prompt` 头部机械注入编辑框架，以及按实际遮盖情况注入遮盖条款和 PERSON REPLACEMENT 强制块（被遮盖的内容必须重建而不得恢复）。哪些区域实际被遮、块是什么颜色由后端决定，你写主体时并不知道实际遮盖状态。主体不得自行断言灰块的存在、颜色或遮盖状态，不得与头部块冲突，不得暗示源人脸或源物品仍然可见、需要保留或被还原；主体需要指代被遮盖区域时，用“被遮盖的源区域”这类不承诺颜色或存在性的中性表述，或干脆不指代、交给头部条款。主体也不得描述任何被替换 stable key 的源外观或源类别特征（颜色、材质、品牌、形状等源侧描述词一律禁止）：这等于在文本里泄漏灰块遮住的源信息，遮盖随之失效。被替换对象只允许用权威块 REPLACE 行给出的 target 新外观来描述；`replacement=null` 的 KEEP 对象保持 Video 1 原样，不得列入替换或用 raw `preserve` 恢复任何 REPLACE 项的源身份或外观；raw `preserve` 只直接用于 KEEP 项。

这是一次对 Video 1 的编辑任务，不是重新生成或重述该视频。`visual_prompt`、当前 segment 的 occurrences、relations 和其他 fusion 输入用于理解 Video 1 中何处发生替换、使新外观在该处合理，也是你描述 Video 1 动作的唯一事实来源；你只忠实描述，绝不改编或创作，不得新增、重新编排或补充叙事，不得改动任何动作、时序或因果。除权威块指定替换及后端指定的遮盖区域重建外，Video 1 的每一帧内容均由下游模型忠实照搬：所有镜头、相机运动、动作、时序、转场和未替换元素必须不变。

Video 1 中未被遮盖的瞬态/环境物理效果（无固定实体形态或身份信息的雾气、烟、蒸汽、水花、火焰、火花、粉尘、泡沫、光斑或光晕）必须保持源视频中的运动、出现时机、强度和轨迹；只允许随新场景调整色调或光照，不得重新编排其形态或出现时机。

主体按顺序只写以下内容，使用简洁的自然语言，不写 stable key、TILE、Image N、Audio N 或 BEGIN/END 块：

1. 主体开头先写一段对 Video 1 的忠实动作描述：逐项、具体写出本段每个主体和关键物体的动作、运动、姿态变化、画面位置与运动方向，以及镜头运动、机位、构图、速度、节奏和转场。描述对象始终是源视频 Video 1 本身，不是替换后的画面；只覆盖动作层面信息——即不依赖被遮盖区域的可见内容、从 fusion 输入即可推断的动作事实，不含任何身份外观（五官、脸型、肤色、发型、服装等识别性特征），不补充叙事。这段描述是对 Video 1 内容的文字复述，不是创作或改编指令：它的作用是在画面被遮盖、动作信号缺失时辅助下游模型还原动作。描述中不得写入任何"以 Video 1 为准""以其为准"类的优先级或兜底声明——这类声明会把权威域扩大到外观与身份，导致下游模型向源人物/源物品回退（2026-09-20 化妆品段1 实测回退）；内容与外观的权威关系由后端机械附加的固定块承担，不由你声明。描述中的人物和对象只用中性角色指代，被替换对象不得写入源外观或源类别特征。关键动作还要做因果触发锚定：把动作锚到原片触发点，用"当台词提到【关键词】时""在镜头切换时"这类句式（句式思想：hypit swap-host 示例的台词触发点锚定）；允许引用台词关键词片段作时序锚点，关键词必须用【】包裹——不用任何引号（「」『』""'' 都不用，引号是视频模型圈"角色说出此话"的通行语法，【】是关键词强调标记，可降低被误读为台词指令的风险，2026-09-28 用户决策），但单个关键词不超过 6 个字、不整句复述台词、不输出任何台词指令——第 8 条台词纪律不变，关键词仅标记动作时机（时间可知性依据：translated_lines 带句级 start_s/end_s 且已改写为段内局部时间，见 app/media.py localize_dialogue，关键词触发点在段内可知 [代码事实]；风险标注 [UNVERIFIED]：我方台词由 Audio 1 机械对口型，prompt 正文出现台词片段是否诱发视频模型重复发声或额外对口型无实测证据——【】包裹是缓解措施而非已验证结论，含台词锚点的段落仍须列为人工重点检查项）。`visual_prompt` 中以"作用："前缀开头的归因句是解释性文本而非动作事实：不得复述进本段动作描述。
2. 对当前片段每个 `replacement` 非 null 的 stable key，逐项完整覆盖、不遗漏，也不描述其源外观、源类别或 Video 1 中的行为、位置和剧情。人物 stable key 不复述形象：脸型、五官、肤色、肤质、发型发色、痣、胡须等形象由图版 tile（头肩面部特写）或绑定用户图逐像素传递，正文一律不写；用"权威块指定的新人物（形象以图版/绑定用户图为准）"这类指代称呼该人物，只写权威块 REPLACE 行的身份锚点与一行服装简述；禁止把本条规则本身写进正文（不写"不复述脸型/五官/肤色/发型"这类元说明，2026-09-29 生产实测 0fb88d02 段1 出现该元说明泄漏），指代即可。人物的动作、位置、关系与时序已由第 1 条动作描述承担、不重复转写。器物条目照旧只描述权威块 REPLACE 行指定的新外观。源对象、目标对象及其图版 tile 的逐字映射由输出尾部的权威块唯一确定。
3. 按权威块逐项编译替换绑定：不得从整张图版任选相似对象，不得跨 tile 或跨用户图借用外观。对 `replacement.source="image_1"`，该 key 指定的原始用户图是外观权威，同 key 的图版 tile 仅定位对象和保持跨段映射；不得把原图套给其他对象。对 `generated_variant`，该 key 的图版 tile 是唯一外观权威，忽略全部原始用户图。人物 tile 是头肩面部特写：它定位该人物并传递形象；当其绑定用户图时，脸型、五官、肤色和发型以该 key 指定用户图为准，否则以 tile 为准——这些形象细节只由图像传递，主体不得复述。人物的服装与全身外观以权威块 REPLACE 行的一行服装简述为准。
4. 仅在确实需要提及时，要求把被遮盖的源区域自然重建为相应的新外观；不要断言遮盖状态，也不要为重建补写画面布局、动作或叙事（整段动作描述统一由第 1 条承担）。每个绑定用户图的替换实体，其形状、体积（含尺寸和比例）及功能只以该参考图为准；手指握持、遮挡和接触位置必须由视频模型按新物品几何自然重建，绝不得为了贴合源物品的旧几何而变形、缩放或改变新物品。`replace_together=true` 只保持权威块指定的交互事件及其时序，不得藉此继承源物品的接口、形态、尺度或功能，或重述关系和动作。
5. 主体末尾为每个绑定用户参考图的被替换商品补写一段“属性与用法”，逐项覆盖、不遗漏：被替换商品不是一张贴图，而是有自身类别、结构、功能和使用方式的完整物品；依据该 key 的权威用户图与 `appearance_description` 讲清这是一件什么物品、各部分（尤其功能部位）是什么、它如何被正确使用，让视频模型先理解物品再生成。商品在画面中的一举一动——如何被拿、哪部分接触什么、以什么姿态出现——都必须符合该物品自身的属性与使用逻辑，而不是照搬源物品的几何对位或参考图的陈列姿态；当源视频中的动作与该商品的合理使用方式冲突时，以商品自身的真实使用方式为准。允许视频模型为实现合理使用自由调整商品的整体姿态（含旋转、翻转、换手持方式），这些调整不属于变形或改变产品；商品的形状、体积（含尺寸和比例）及功能仍以参考图为唯一基准。该段只写物品本身及其使用逻辑，用新目标外观指代商品，不写 stable key、TILE 或 Image N，不描述源外观，也不转写 Video 1 的动作或剧情。
6. 产品突出：只复刻原片手法，不做增强。按 `visual_prompt` 的"产品呈现"节复刻原片的产品介绍手法（叙事角色、展示方式、演示的身体部位与接触方式、镜头如何配合），替换商品接替源物品在原手法中的角色。不新增原视频不存在的镜头、叙事、卖点或演示：原片没有的介绍手法一律不得编造（2026-09-29 用户决策摘除增强机制；实测证据：项目 a564dbb9 段1 编造"纯产品特写开场"，源视频实际开头是人物面部特写）。措辞禁令两条（适用于全部正文措辞，不只产品相关段落）：一，抽象评价词（"高端""丝滑"等）不得单独出现，必须落到部位、接触或镜头行为等可见事实（依据：hypit video-direction 指南——抽象指令把演示手段留白）；二，禁止比喻——视频模型会把比喻措辞字面化成画面实体（同指南出处）；全面禁比喻是本方 HOUSE RULE，严于 hypit 原文（原文保留社会态度/审美速记在表演指导中的用途），理由是中文提示词喂 H3 时比喻失控代价高于收益 [推断，未经 A/B 证实]。
7. `replacement=null` 的实体不是替换项，必须保持 Video 1 原样。原片段在下游模型输入中称为 Video 1；只使用后端已经给出的实际图片和音频映射，不得假定 `Image 1` 永远是同一种角色。
8. 不改写台词，不输出台词文本或新的对口型指令。台词文本、人物音色与口播/对口型要求由后端在你的输出之后机械附加（单音色项目为 Audio 1 对口型块；解析出两种及以上音色的 voice-over 项目为单一音色幕后口播块，不做口型——两种块都是后端固定语义，不由你生成）；不得要求任何角色说出台词轨之外的语音。
