# Round5 四单闪烁问题实证分析报告

日期：2026-09-08。分析对象：`data-verify/projects/` 下四单（漱口水 2be14a82、狗 80e34503、项链对照 2be0b352 / 331ef2d1）。全部结论基于中间产物实测，证据帧在 `analysis/evidence/`，扫描脚本与原始数据在 `analysis/`（`scan_mask_leaks.py`、`scan_true_leaks.py`、`mask_scan.json`、`mask_true_leaks.json`、`mask_block_components.json`）。

## 给主代理的 200 字结论

用户"中段漏灰块→H3 还原原脸"的假设**被否证**：漱口水和狗两单的人脸遮罩逐帧完整（源视频检出的人脸框在打码视频中灰块覆盖率全部达标，true_leaks=0；打码后视频上的 YuNet 复检命中全部是**手部误报**）。真正发现的遮罩 bug 是反向的：YuNet 会把手误判成脸，于是打码阶段**间歇性地把手（和手持物）也盖上灰块**——狗单的替换目标 person-01 恰恰是手，输入视频里手"时而是原手、时而是灰块"，H3 输出随之不稳，甚至把灰块原样复制进成片（狗单成片 t≈12.26s 有一帧手的位置是纯灰块）。狗的"时而新时而旧"主要是**视角级不一致**：正脸镜头换成了棕色新狗，背身/侧身镜头保留原灰毛狗。漱口水成片在 1fps/2fps/满帧率抽样下身份与 Listerine 均稳定，未见段级或段内回退。项链对照组反而存在真实漏脸（段首脸部半出画，YuNet 漏检），但未产生用户投诉。

## 1. 灰块漏帧检测（任务 1）

- **交叉验证**（更严格）：在**源视频** `source.mp4` 上逐帧跑 YuNet，对每个检出框（含 face_mask.py 同款 45%/75%/50% padding）检查打码视频同帧同位置的灰块覆盖率，<50% 记 true leak。

## 3. 替换物闪烁路径（任务 3）——真正的发现

### 3.1 提示词段间一致性

四单所有段的 `h3_prompt.txt` 头部强制换脸指令逐字相同；同一实体的 REPLACE 子句在出现的各段间逐字一致（如漱口水 entity-01 Listerine 在 seg1/4/5 完全相同，狗 entity-02 木梳在 seg1/2 完全相同）。reference sheet 均为单张全局 sheet（state.json `replacement_sheet` status=succeeded）。**排除"段间提示词强度不一致"假设。**

### 3.2 打码阶段的手部误遮罩（新发现的 bug）

对打码视频做灰块连通域分析（`mask_block_components.json`）：除人脸主块外，存在**间歇性额外灰块**：

- **狗 80e34503**：
  - seg2：t=0-0.87s 连续 + t=1.0-1.77s + 散点 t=1.87/2.07/2.13-2.2/2.53/2.63/2.73/2.8-2.87/3.07-3.53/4.9/5.2/5.63-5.67/7.0-7.1s。证据 `dog2_cmp_t0.5.jpg`、`dog2_cmp_t4.9.jpg`：灰块盖的是**拿梳子的手/前臂**——而 person-01 的替换目标正是这只手。输入里手"时而原手时而灰块"。
  - seg1：t≈7.17-7.97s（沥青地面特写）手被间歇遮罩。
- **漱口水 2be14a82**：seg1 t=0.07-1.03s、seg2 t=5.67-5.73s、seg4 t=0.03-0.87s、seg5 t=2.07s，额外灰块位于画面下部手/瓶区域（面积 3-15%）。

### 3.3 灰块泄漏进成片（狗单实锤）

狗单 seg2 的 H3 原始返回在 **t=2.458s 有一帧完整灰块**（占画面 8%，位于手的位置），且该时间点输入并无灰块——H3 从邻帧"学会"并复制了灰块。该帧进入成片 `output/generated.mp4` **t≈12.26s**：证据 `dog_out_grayblock_cmp.jpg`（t=12.20/12.26/12.33 三联图，中间帧手的位置是纯灰矩形，前后帧正常）。

### 3.4 替换物时间曲线（抽帧目检）

- **狗单**（`dog_h3_0001_grid.jpg`、`dog_h3_0002_grid.jpg`、`dog_out_2fps_grid.jpg`、密采 `dog2_h3_0_25_grid.jpg`）：
  - 木梳：所有采样点均为新木梳，**段内无回退**。
  - 狗：**视角级不一致**——背身镜头（seg1 t=0-4s、seg2 侧身镜头）保留原灰黑长毛（证据 `dog1_cmp_t2.0.jpg`），正脸镜头换成巧克力棕新狗（`dog1_cmp_t5.0.jpg`）。这就是用户看到的"狗时而新时而旧"，但它是**分镜级**而非逐帧闪烁。
  - 手：除 3.3 的灰块帧外，各采样点手部外观大体一致；输入手部间歇遮罩的影响主要体现在该灰块帧和局部肤色不稳。
- **漱口水单**（`mw_h3_000{1,4,5}_grid.jpg`、`mw_out_2fps_grid_{a,b}.jpg`、满帧率密采 `mw1_h3_0_16_grid.jpg`、`mw4_h3_0_13_grid.jpg`）：新人身份与 Listerine 瓶在所有采样窗口稳定，**未见段级或段内回退**。用户报告的"换人没换人再到换人"在本次抽帧中未复现；由于人脸遮罩逐帧完整，若观看时确有身份闪变，机制只能是 H3 生成内随机性，而非遮罩泄漏。

## 4. 结论与机制归因

1. **漏脸帧**：漱口水/狗**不存在**；项链对照组存在（段首半出画脸部，YuNet 漏检，约每段 1-6 帧）但未造成可见身份回退。用户"灰块漏帧→还原原脸"假设否证。
2. **替换物闪烁级别**：狗单为**分镜/视角级不一致**（正脸换、背身不换），非段内逐帧闪烁；漱口水单抽样未见回退。提示词段间无差异，排除提示词路径。
3. **最可能机制**（按证据强度排序）：
   - a) **YuNet 手部误检导致打码阶段间歇性遮罩手/手持物**（实锤，含一帧灰块泄漏进成片）——对"替换目标含手/手持物"的单子会直接造成输入时序不一致，诱导 H3 输出不稳。修复方向：打码只对"人物脸部"生效，需过滤手部误检（如按框位置/尺寸与人物跟踪绑定，或对 person 类替换目标为"手"的 case 禁用脸部打码之外的块）。
   - b) **H3 对无脸视角（背身/侧身）保留源外观**：狗的背身镜头没有脸部特征可锚定 sheet 图版，H3 倾向保留源毛色。修复方向：提示词/图版强化"全身各视角"约束，或对背身镜头接受部分不一致。
   - c) H3 生成内随机性：无法从产物进一步分离，但漱口水单的身份闪变（若观看确认存在）只能归于此。
4. **附带发现**：项链类素材段首半出画脸会漏打码（两单一致），本次未造成投诉，但属于真实漏检点，建议在 face_mask 增加"出画半脸"场景的兜底（如降低阈值或对段首帧加严）。
