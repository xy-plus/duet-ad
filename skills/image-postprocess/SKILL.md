# image-postprocess

## 目标

为了降低素材重复度，在关键帧进入视频生成前，为可能执行的 Seedream 二次编辑生成提示词。第一优先级是最终视频连续性和现实合理性；任何扭曲、元素突变、物理或接触关系异常都一票否决。人物或背景替换仅是用于去重的第二优先级，只有通过第一层才评价。

本 Skill 只生成提示词，不编辑图片、不调用 Seedream。生成提示词不代表图片二次编辑一定执行、成功或被视频生成采用。

## 输入

只允许读取：

- `work/request.json`：
  - `edit_mode` 只能是 `anchor_consistency` 或 `independent_parallel`。
  - `segments` 按段号升序提供 `index`、`chain_id`、`join_mode`。
  - 短视频只有第 0 段；多段视频的段号从 1 连续递增。
- `work/segments/<段号>/keyframes/01.png、02.png …`：对应片段的全部冻结关键帧。

不得读取视频、视频生成提示词、台词、音频、项目目录、其他路径或未列出的文件。

## 唯一输出

只写 `work/image_optimization.json`，不得写其他文件。输出必须是 UTF-8 JSON，结构严格如下：

```json
{
  "version": 1,
  "segment_indices": [1, 2],
  "global_elements": [
    {
      "id": "PERSON_01",
      "kind": "person",
      "source": "跨段重复出现的原人物可见特征",
      "replacement": "统一的新人物身份和可复用外观特征",
      "segments": [1, 2]
    }
  ],
  "segment_prompts": [
    {
      "segment_index": 1,
      "prompt": "本段真实提交给 Seedream 的完整提示词"
    },
    {
      "segment_index": 2,
      "prompt": "本段真实提交给 Seedream 的完整提示词"
    }
  ]
}
```

- `segment_indices` 必须与请求段号完全一致。
- `segment_prompts` 必须覆盖全部段并按段号升序排列；每段提示词非空，以 Unicode 字符数计不超过 120 个字符。
- 短视频的 `segment_indices` 是 `[0]`，`global_elements` 必须是空数组。
- 除规定字段外不得增加字段；不得用 Markdown 代码围栏包裹 JSON。

## 项目级安全决策

1. 先检查全项目全部关键帧，再决定替换策略；去重目标只能是 `人物外观` 或 `背景`。把同一 `chain_id`，或可见为同一人物、同一核心前景对象或同一互动关系的段连成相关组件；不可见的信息不得推断或虚构。
2. 若相关段包含任何功能道具、商品、玩具或人与物互动，整个相关组件统一只替换背景。相关段的人物和服装不得变化，所有前景对象、像素语义和关系都保持不变。
3. 背景替换只设计同类别、同功能、同类型但不重复且真实的背景。跨段同类背景必须逐字复用同一个 `SCENE replacement`，不得逐段改写同一个新设计。
4. 只有全项目完全没有核心前景互动、人物稳定清晰且同一人物在所有拟替换段都可确认，人物替换也不会降低连续性和现实合理性时，才允许项目级统一人物替换。新人物保持可见的性别呈现、相近年龄和整体气质，长相略有不同；不得推断身份或具体族裔，服装与背景不得变化。
5. 未同时满足人物替换全部条件时选择背景。画质、功能道具、玩具、商品、宠物不得作为差异化目标；没有人物时不得新增人物。

## 不可编辑内容

- 核心商品、功能道具、玩具、手部，以及人与物/物与物的握持、接触、插入、对齐、连接、遮挡、前后顺序、数量、结构、方向，全部不可编辑；不得同类改款。
- 保持目标帧自身的画幅、裁切、机位、镜头、透视、景别、构图、光线、焦点、景深、人物与动物数量、姿态、动作、视线，以及非目标元素的位置、比例和可见部分。
- 提示词只点名目标帧中最容易误改的剧情核心物体和关系，不复述全部构图或叙事，不描述视频过程、运镜、转场、台词或音频。
- 禁止恢复或新增字幕、文字、Logo、水印、贴纸、界面元素、品牌标识或乱码。

## 跨段一致性

1. `global_elements` 只允许 `PERSON`、`OUTFIT`、`SCENE`；PROP、PRODUCT、SUBJECT 不得建立新映射。只有真正被替换且跨至少两段重复的元素才进入，单段元素和仅被保持的元素不进入。
2. 人物使用 `PERSON/person`，人物目标中一并替换的服装使用 `OUTFIT/outfit`，背景使用 `SCENE/scene`。同类 ID 从 `01` 连续编号；整个数组按完整 `id` 的字典序输出。
3. `source` 只写识别原目标所需的稳定可见特征；`replacement` 只写可直接复用的新身份或新设计，不写构图、动作、光线、位置或关系。
4. `segments` 只列实际执行该替换的段号，升序、去重且至少包含两段。背景策略的跨段同类背景必须逐字复用同一个 `SCENE replacement`。
5. 同一 `chain_id` 的 `continue` 段优先视为连续画面；`hard_cut` 不自动代表人物或场景变化，仍以可见证据判断。

## 每段 Seedream 提示词

每段所有关键帧共享一份可直接提交给 Seedream 的提示词，不得包含 Markdown、解释或分析。每段提示词恰好两句，并遵守以下硬约束：

1. 背景策略的第一句只写同类别、同功能但不同的背景，并保持透视、光线方向和地面接触；不得要求人物重绘或服装变化。极少数安全人物策略的第一句只写全项目统一的 `PERSON replacement`，并明确服装与背景不变。
2. 第二句保护全部前景像素语义，只点名一个最危险关系，并禁止文字或 Logo。不得写第二个关系、全景复述、物体清单、画质美化、真实摄影增强或其他编辑目标。

把模式约束压入第二句：`independent_parallel` 说明当前图是唯一目标；`anchor_consistency` 说明当前图是目标，其他图只提供所选目标的身份或背景设计参考，不能传递构图、动作、物体或关系。

不得使用固定长开头或额外句子。生成前自行计数整段提示词的 Unicode 字符数；超长必须重写，不能截断。确认第一层安全门槛、两句结构、单一目标和所有不可编辑关系均满足后，才写入 JSON。
