# image-postprocess

## 目标

第一优先级是最终视频连续性和现实合理性；任何扭曲、元素突变、物理或接触关系异常都一票否决。保持叙事内核和关系不变，只改变表象。人物或背景替换仅是用于去重的第二优先级，只有通过第一层才评价。

本 Skill 只生成提示词，不编辑图片、不调用 Seedream。生成提示词不代表图片二次编辑一定执行、成功或被视频生成采用。

## 输入

只允许读取：

- `work/request.json`：`edit_mode` 只能是 `anchor_consistency` 或 `independent_parallel`；`segments` 按段号升序提供 `index`、`chain_id`、`join_mode`。
- `work/segments/<段号>/keyframes/01.png、02.png …`：对应片段的全部冻结关键帧。

不得读取视频、视频生成提示词、台词、音频、项目目录、其他路径或未列出的文件。

## 唯一输出

只写 UTF-8 `work/image_optimization.json`，不得写其他文件，结构严格如下：

```json
{
  "version": 1,
  "segment_indices": [1, 2],
  "global_elements": [
    {
      "id": "PERSON_01",
      "kind": "person",
      "source": "跨段重复出现的原人物可见特征",
      "replacement": "统一的新人物身份和可复用外观特征",
      "segments": [1, 2]
    }
  ],
  "segment_prompts": [
    {"segment_index": 1, "prompt": "本段真实提交给 Seedream 的完整提示词"},
    {"segment_index": 2, "prompt": "本段真实提交给 Seedream 的完整提示词"}
  ]
}
```

- `segment_indices` 必须与请求段号完全一致。
- `segment_prompts` 必须覆盖全部段并按段号升序排列；每段提示词非空、恰好两句。
- 短视频的 `segment_indices` 是 `[0]`，`global_elements` 必须是空数组。
- 除规定字段外不得增加字段；不得用 Markdown 代码围栏包裹 JSON。

## 项目级安全决策

### 可观察定义

- 核心实体：删除或修改后会改变动作目的、剧情含义或画面识别的可见实体。
- 交互实体：与人物或核心实体存在持握、接触、装配、插入、连接、对齐或承托等可见关系的实体。
- 非目标前景：遮挡目标编辑域，或建立景深、接触边界的可见实体。
- 交互支持区域：任何物理表面若直接承托核心实体、接收核心实体或交互实体的落点、承载可见动作轨迹、被流体或颗粒接触、经过或扩散，或承载可见功能过程，即属于交互支持区域。
- 高风险关系：上述任一可见关系存在，或物理表面属于交互支持区域，且编辑对象变化可能破坏数量、结构、作用方向、接触点、遮挡或前后顺序。

### 决策步骤

1. 先检查全项目全部关键帧；去重目标只能是 `人物外观` 或 `背景`。全项目构建跨段相关组件：把同一 `chain_id`，或可见为同一人物、同一场景或同一稳定背景编辑域、核心实体、交互实体、非目标前景或互动关系的段连在一起；识别核心实体、交互实体及实体间互动，不得用不可见信息推断或虚构关联。
2. 每个组件只做一次策略选择并冻结，不得逐段摇摆。逐帧检查核心实体与交互实体之间的空间与物理关系，以及所有交互支持区域；交互支持区域计入高风险关系。任一相关段存在高风险交互关系，整个组件统一选择背景路线，只替换背景；人物、服装、核心实体、交互实体、非目标前景、交互支持区域及其像素语义、空间与物理关系全不变。
3. 背景路线只选一个可追踪的物理背景元素或稳定且完整闭合的环境背景域作为编辑域。物理元素编辑域可以包含同一元素的多个可见部分或不同朝向面，但不得合并不同物理元素；环境背景域必须通过下述专用门禁。允许个别关键帧因裁切不可见，该帧不做其他编辑；不得把未被闭合边界纳入的其他背景并入编辑域。
4. 对所选背景编辑域只做原位外观映射，默认只改变一种低频外观属性，优先色相；只有色相不适合作为安全差异时，才单独选择明暗、光泽或粗糙度之一。`SCENE replacement` 和项目级替换短语只写实际改变的一个属性，不得列出未改变属性或多个候选；选择色相时遵守下述 hue-only 契约。完整保留原纹理图案、纹理相位、缺陷、边界与几何，包括方向、透视、尺度和接触几何，并保持光线方向；不得新增、删除或移动纹理图案、接缝、重复单元或高频细节；固定构件和边界结构的几何与位置不得改变。不得描述或生成新环境。
5. 背景编辑域不合格不自动等于整个组件不改动；背景域收紧不得把该条件分支改为普遍不改动。当背景候选尚未建立或整体失败，且找不到稳定安全的背景编辑域，并且组件无高风险交互关系、同一人物在所有相关段稳定清晰且换脸安全时，统一走人物路线且仅换脸；换脸安全要求同一人物可确认，且不会降低连续性和现实合理性。只替换同一人物的新脸，新脸长相略有不同；保持可见的性别呈现、肤色和整体风格、年龄和气质，不推断身份或具体族裔；只换脸，不换服装，锁定头部位置、大小、朝向、裁切和遮挡；跨段 `PERSON replacement` 必须逐字复用。
6. 任何组件只要背景路线和人物路线都不能证明安全，就输出两句不改动提示词，不建立 `global_elements`；这包括无人、人物不清晰且无稳定安全背景编辑域的普通组件。高风险组件找不到合格背景编辑域时放弃去重，不得退到人物路线。画质、核心实体、交互实体、非目标前景不得作为差异化目标；没有人物时不得新增人物。

### 背景候选类型冻结

- 每个背景候选必须在证据评估前且仅一次分类为有限物理元素或闭合环境背景域，分类结果在该组件内冻结。两种类型都必须由候选自身的可见正向证据证明；环境背景域不是物理元素门禁失败后的默认兜底。
- 具有独立物理身份与自身外轮廓的候选属于有限物理元素。任何具有可触碰或承载的材质表面、结构平面、附着表面，或具有属于物质表面的自身纹理拓扑，或属于有限物体或构造的区域，都必须分类为有限物理元素，即使填满背景或视觉上由画幅边与遮挡闭合。有限物理元素永远只能通过物理元素门禁，不得借用环境背景域规则重新分类、缩小、扩大或救活。
- 闭合环境背景域只适用于身份本身就是画幅内闭合视觉场的区域，且必须是无有限物质表面且无自身物理外轮廓的稳定环境视觉场；可见边界只能由画幅边与不可编辑前景或遮挡物的原外轮廓形成，不得由有限物理元素或其周边区域改名构造。表面折转、材质分界、颜色分界、照明分界或构造内部边界不得用于构造闭合环境背景域。
- 任一资格门失败即终止该候选，不得更换标签或调整成员边界后重试；分类不确定时该候选失败，不得回退为环境背景域。这不阻止独立候选按自身冻结类型接受评估。

### 背景 SCENE 逐段证据

- 背景 `SCENE` 规则中的“相关段”仅指列入该 `SCENE segments` 的合格段；`SCENE segments` 只包含通过逐段证据门禁的合格段。同一组件已有至少两个合格段并建立 `SCENE`，但另有一个或多个不合格段时，每个不合格整段必须输出两句不改动提示词，不得包含该 `SCENE` 的项目级替换短语，也不得改走人物路线。
- “同一场景”只用于构建相关组件，不能证明背景编辑域跨段为同一目标。每个拟列入 `SCENE segments` 的段必须用该段自身关键帧独立举证；不得用其他段、场景名称、语义类别相同或相似材质补证。
- 对物理背景元素候选，目标表面的定位不得只依赖语义名称。局部停止边界必须是冻结编辑域通向不同物理元素的外部边界，外部边界另一侧保持原样；内部几何折转或同一物理元素内部边界不得作为停止地标。背景候选评估时无法稳定定位编辑域，就判该候选不合格并返回组件级决策；组件已经建立背景 `SCENE` 或因高风险交互冻结为背景路线后，个别因编辑域无法稳定定位而不合格的段必须输出两句不改动提示词，不得逐段改走人物路线。
- 对物理背景元素候选，每个拟编辑段的每个目标可见帧都必须独立提供证据：该帧中目标表面的身份、连续可编辑区域、边界和原纹理拓扑清晰可辨，且目标每个可见部分在图内的完整原外轮廓、外轮廓转折和遮挡边缘清晰可定位，足以按原位置保留；不得用段内其他帧补证。任一目标可见帧不满足，该段的背景候选即不合格，不得把该段列入 `SCENE segments`；若任一目标可见帧仅见模糊、小面积、遮挡到无法判界或不同朝向局部且无法确认同一表面，也按上述不合格处理。
- 同一 `SCENE` 要求各合格段的可见证据证明它们属于同一物理背景元素，或属于同一稳定且完整闭合的环境背景域；仅同类或同一局部平面不够。`hard_cut` 不自动否定同一物理元素或同一环境背景域，但每个段必须独立举证。
- 单个段内目标偶尔因裁切完全不可见时，该帧可以不改动，但该段整体资格必须由该段自身所有目标可见帧分别通过上述逐帧证据门禁。过滤后最终少于两个合格段时不得建立背景 `SCENE`，继续按人物仅换脸或不改动决策。

### 环境背景域门禁

- 环境背景域可以延伸到画外，但每个目标可见帧内完整可见域的可见边界只能由画幅边与不可编辑前景或遮挡物的原外轮廓形成，身份与拓扑跨帧稳定；不得只凭颜色、空白或画面位置识别。
- 边界和遮挡必须由每帧独立举证，不得跨帧补证；任一目标可见帧无法完整定位闭合边界、原轮廓或遮挡边缘时，该段的环境背景域候选即不合格。
- 环境背景域不得直接承托人物、核心实体或交互实体，也不得与其存在可见物理接触，不得接收其落点，不得承载动作轨迹、流体或颗粒的接触、经过或扩散以及功能过程。任一部分属于交互支持区域，整个环境背景域即不合格；该一票否决条件不得通过缩小或拆分候选绕过。

### 背景 SCENE 编辑域成员冻结

- 冻结目标是一个可追踪的物理背景元素或稳定且完整闭合的环境背景域。在项目/组件级冻结编辑域成员关系，先确定哪些物理部分或闭合区域纳入、哪些排除；物理元素编辑域可以包含同一元素的多个可见部分或不同朝向面。同一成员在所有目标可见帧中必须统一纳入或排除，不得随帧改变。
- 不同视角下的局部可见边界只用于定位同一冻结编辑域，不能改变成员集合；本段局部停止边界可以不同，但只能对应同一批物理成员。
- 多平面或相邻连续部分只有在逐帧无歧义追踪同一成员集合时才合格。对于已因高风险交互冻结为背景路线的组件，成员关系不确定时必须在规划阶段令整个相关组件输出两句不改动提示词；该整组件结论优先于逐段合格过滤，不得逐帧漏改，也不得回退人物路线。无高风险交互关系的组件仍按项目级安全决策评估安全的人物仅换脸路线。

## 不可编辑内容

- 核心实体、交互实体、非目标前景、交互支持区域，以及实体间的空间与物理关系、数量、结构、方向，全部不可编辑；交互支持区域不得作为背景候选或差异化目标；不得同类改款。
- 保持目标帧自身的画幅、裁切、机位、镜头、透视、景别、构图、光线、焦点、景深、人物及其他实体的数量、姿态、动作、视线，以及非目标元素的位置、比例和可见部分。
- 禁止恢复或新增字幕、文字、Logo、水印、贴纸、界面元素、品牌标识或乱码。

## 跨段一致性

1. 本 Skill 的 `global_elements` 只允许 `PERSON`、`SCENE`；不得输出 `OUTFIT`、`PROP`、`PRODUCT`、`SUBJECT`。只收录实际跨段替换且跨至少两段重复的 PERSON 或 SCENE；单段或仅保持的元素不进入。
2. 人物使用 `PERSON/person`，背景使用 `SCENE/scene`；同类 ID 从 `01` 连续编号，数组按完整 `id` 的字典序输出。
3. `source` 只写原目标的稳定可见特征；`replacement` 只写可复用的新脸或新设计，不写构图、动作、光线、位置或关系。
4. `segments` 只列实际替换的段号，升序、去重且至少两段。每个背景组件只为选中的一个背景编辑域建立 `SCENE`；为同一背景目标冻结项目级替换短语，由“目标背景描述 + 实际改变的一种低频属性及其目标值”组成，`SCENE replacement` 逐字记录该短语。选择色相时，项目级替换短语和每段第一句必须明确写“只旋转色相”，项目级替换短语使用“目标背景描述 + 只旋转色相到目标色相类别”；人物路线逐字复用同一 `PERSON replacement`。
5. 同一 `chain_id` 的 `continue` 段优先视为连续画面；`hard_cut` 不自动代表人物或场景变化，仍按可见证据判断。

## 每段 Seedream 提示词

每段所有关键帧共享一份可直接提交给 Seedream 的提示词。第一句只聚焦唯一替换目标及其原位条件；第二句写完整保护。保持简洁，但不得为缩短删除安全关系；禁止全景复述、画质美化或实体清单。不得包含 Markdown、解释或分析。

每个 `segment_prompts.prompt` 必须直接写自然语言目标与替换设计，绝不能包含内部 ID 或字段标签，例如 `PERSON_01`、`SCENE_01`、`source`、`replacement`、`global_elements`；这些只属于 JSON 映射。

### 背景路线

1. 选择色相时，目标色只使用不携带明度、感知亮度、饱和度或表面处理含义的色相类别；不得使用明亮、浅、深、鲜艳、柔和、均匀或哑光修饰目标色相，也不得使用“明显”等程度修饰。环境背景域只允许上述 hue-only 映射，不启用其他属性备选；无法安全取得合规差异时允许不改动，不得强行复杂重画。
2. hue-only 必须使同一输入像素或同一物理区域的原明度或感知亮度与原饱和度保持不变，不得抬亮暗部或压暗高光；逐帧继承原图的局部对比、亮度分布、渐变方向、渐变幅度和原有低频结构，以及原光照、阴影、反射、纹理图案、纹理相位、缺陷、光泽和粗糙度。跨帧同一原始明度必须映射为同一输出明度，不得把目标域统一填充成固定亮度；完整保留原边界与几何，不得新增、删除或移动纹理图案、接缝、重复单元或高频细节。成员关系或成员边界不确定时必须在规划阶段不建立该域，已冻结为背景路线的高风险组件则整组件不改动；合格提示词必须完整覆盖已冻结成员。
3. `SCENE replacement` 不直接提交给 Seedream。为同一背景目标冻结项目级替换短语；每个相关段逐字复用，不得缩写、改写或使用同义词。第一句最前面先写 hue-only 及其通道不变量，再写编辑域边界；选择色相时以项目级替换短语开头。项目级替换短语在合格段间逐字一致，但每段 `prompt` 可写该段不同的局部可见外部边界；局部停止边界不属于项目级替换短语，不要求整段 `prompt` 或整句逐字相同，其余关系保护可按本段可见关系写，但不得改动项目级替换短语。第一句要求完整覆盖已冻结编辑域，不得只修改其中局部；每张图完整覆盖全部可见成员，不得局部应用；只编辑本图可见的冻结编辑域，目标不可见的图片不做任何改变；严格沿本图中冻结编辑域每个可见部分的原外轮廓、外轮廓转折和遮挡边缘停止，保持轮廓几何，禁止补全、拉直、平滑、扩张、收缩、改形或产生边缘光晕；环境背景域还必须说明本图闭合边界只由画幅边与不可编辑前景或遮挡物的原外轮廓构成；写明本段局部可见外部边界并要求外部边界另一侧保持原样，内部几何折转和同一物理元素内部边界仍不作为停止线，不得与外轮廓混淆；保持方向、透视、尺度、接触几何和光线方向，禁止编辑外溢到目标编辑域之外；不得描述新环境、诱导新增非目标实体、重绘人物或改变服装。
4. 第二句要求仅目标域发生所选属性变化，并合并全部非目标冻结；禁止全局调色、白平衡、曝光、对比度或重新布光，目标域外保持原颜色与明暗；冻结编辑域边界外全部保持不变，明确固定构件和边界结构不得新增、删除或移动，非目标前景继续遮挡目标编辑域，接触点、接触阴影、反射和边界结构不得改变；人物、服装、核心实体、交互实体、非目标前景及实体间空间与物理关系全不变；禁止增删文字或 Logo，禁止真实摄影增强或其他编辑目标。

### 人物路线

1. 第一句只替换同一人物的新脸；保持可见的性别呈现、肤色和整体风格、年龄和气质，锁定头部位置、大小、朝向、裁切和遮挡。只换脸，不换服装、背景或身体其他部分。
2. 第二句明确固定构件和边界结构不得新增、删除或移动；人物除脸外、服装、核心实体、交互实体、非目标前景及实体间空间与物理关系全不变，并禁止增删文字或 Logo。

把模式约束压入第二句，不得增加第三句：`independent_parallel` 无需写“当前图是唯一目标”，不得写参考人物、参考角色或其他图；`anchor_consistency` 必须限制其他图的角色，说明其他图只提供目标设计，不传递人物、构图、动作、实体或关系。
