# image-postprocess

## 目标

为了降低素材重复度，在关键帧进入视频生成前，为可能执行的 Seedream 二次编辑生成提示词。每段只替换一个主要目标，其余画面内容和关系保持不变；同一替换目标跨段出现时复用同一个新设计。

本 Skill 只生成提示词，不编辑图片、不调用 Seedream。生成提示词不代表图片二次编辑一定执行、成功或被视频生成采用。

## 决策优先级

1. 最终视频连续性和现实合理性是第一优先级。先判断候选替换能否保持跨帧、跨段连续并符合现实物理；任何可能造成扭曲、元素突变、物理关系异常、接触关系异常的候选都一票否决，必须丢弃并重新路由或重写。
2. 人物或背景替换去重是第二优先级。只有通过第一层硬门槛，才评价重复度和替换收益；不能因为更不重复而接受连续性或现实合理性风险。
3. 该优先级只约束内部选择和提示词，不得增加输出字段，不得放宽恰好两句和 140 字上限。

## 输入

只允许读取：

- `work/request.json`：
  - `edit_mode` 只能是 `anchor_consistency` 或 `independent_parallel`。
  - `segments` 按段号升序提供 `index`、`chain_id`、`join_mode`。
  - 短视频只有第 0 段；多段视频的段号从 1 连续递增。
- `work/segments/<段号>/keyframes/01.png、02.png …`：对应片段的全部冻结关键帧。

不得读取视频、视频生成提示词、台词、音频、项目目录、其他路径或未列出的文件。

## 唯一输出

只写 `work/image_optimization.json`，不得写其他文件。输出必须是 UTF-8 JSON，结构严格如下：

```json
{
  "version": 1,
  "segment_indices": [1, 2],
  "global_elements": [
    {
      "id": "PERSON_01",
      "kind": "person",
      "source": "跨段重复出现的原人物可见特征",
      "replacement": "统一的新人物身份和可复用外观特征",
      "segments": [1, 2]
    }
  ],
  "segment_prompts": [
    {
      "segment_index": 1,
      "prompt": "本段真实提交给 Seedream 的完整提示词"
    },
    {
      "segment_index": 2,
      "prompt": "本段真实提交给 Seedream 的完整提示词"
    }
  ]
}
```

- `segment_indices` 必须与请求段号完全一致。
- `segment_prompts` 必须覆盖全部段并按段号升序排列；每段提示词非空，恰好两句，整段不超过 140 个 Unicode 字符。
- 短视频的 `segment_indices` 是 `[0]`，`global_elements` 必须是空数组。
- 除规定字段外不得增加字段；不得用 Markdown 代码围栏包裹 JSON。

## 项目级风险路由与单一目标

1. 先检查全项目全部关键帧，再为任何片段写提示词。识别跨段重复的 PERSON、OUTFIT、SCENE；以片段为节点、跨段重复元素为连接，求传递后的相关段闭包，形成互不重叠的跨段相关组件。不得按段独立猜测后再拼接。
2. 在每个跨段相关组件内一次性冻结唯一类别，严格二选一：`人物外观`或`背景`。同一人物相关段不得一段换人物、一段换背景；组件冻结后，其全部相关段都服从该类别。
3. 风险优先：若任一相关帧出现手部与功能道具的握持、插入、安装、发射、遮挡高风险，整个相关组件统一选择背景。否则，只有各相关段的人物脸部和服装足够可见、能建立稳定同一性，即人物清晰稳定时，才优先选择人物外观，并让整个相关组件统一选择人物外观；其余情况统一选择背景。
4. 组件路由不能放宽段内约束：段内仍只能有一个替换目标。若同一段可命中多个候选，只保留一个主要目标，不得同时替换人物外观和背景，也不得增加第二个人物或第二个背景目标。
5. `人物外观`指一个人物的新面孔；可连同同色、同用途、同风格但不同款的服装一起设计，并仍视为同一个人物替换目标。新人物保持可见的性别呈现、相近年龄和整体气质，长相略有不同；不推断身份或具体族裔。选择人物外观时不得修改背景；选择背景时不得修改人物或服装。
6. 背景替换保持场景类别与功能，只设计同类型但不重复的真实背景；不得借背景替换改动前景主体、核心物体或关系。没有人物时不得新增人物；不可见的信息不得推断或虚构。
7. 画质、功能道具、玩具、商品、宠物不得作为差异化目标。禁止画质美化、全场景复述、道具改款。

## 不可编辑内容

- 核心商品、功能道具、玩具、手部，以及人与物/物与物的握持、接触、插入、对齐、连接、遮挡、前后顺序、数量、结构、方向，全部不可编辑；不得同类改款。
- 保持目标帧自身的画幅、裁切、机位、镜头、透视、景别、构图、光线、焦点、景深、人物与动物数量、姿态、动作、视线，以及非目标元素的位置、比例和可见部分。
- 提示词只点名目标帧中最容易误改的剧情核心物体和关系，不复述全部构图或叙事，不描述视频过程、运镜、转场、台词或音频。
- 禁止恢复或新增字幕、文字、Logo、水印、贴纸、界面元素、品牌标识或乱码。

## 跨段一致性

1. global_elements 只允许 PERSON、OUTFIT、SCENE，且只有真正被替换并跨段重复的元素才能进入；PROP、PRODUCT、SUBJECT 不得建立新映射。只出现于一段或仅被保持的元素不进入 `global_elements`。
2. 人物使用 `PERSON/person`，人物目标中一并替换的服装使用 `OUTFIT/outfit`，背景使用 `SCENE/scene`。同类 ID 从 `01` 连续编号；整个数组按完整 `id` 的字典序输出，不按发现顺序或片段顺序输出。
3. `source` 只写识别原目标所需的稳定可见特征；`replacement` 只写可直接复用的新身份或新设计，不写构图、动作、光线、位置或关系。
4. `segments` 只列实际执行该替换的段号，升序、去重且至少包含两段。相同替换描述必须跨段逐字复用。
5. 同一 `chain_id` 的 `continue` 段优先视为连续画面；`hard_cut` 不自动代表人物或场景变化，仍以可见证据判断。

## 每段 Seedream 提示词

每段所有关键帧共享一份可直接提交给 Seedream 的提示词，不得包含 Markdown、解释或分析。提示词恰好两句，以句号结束；不得用分号、冒号或并列祈使句伪装第三句。整段生成后按 Unicode 码点计数，不超过 140 个 Unicode 字符。

1. 第一句只写替换目标及具体新设计；人物目标可包含其配套服装，背景目标不得包含人物变化。不得写保持关系、画质要求或全场景描述。
2. 第二句只锁定最危险关系和其余内容不变：只点名该段全部关键帧中最容易误改的一个核心物体、手部或关键关系，并以“其余内容不变”收束。不得加入第二个关系、禁止项清单、真实摄影要求或道具改款。

模式说明保持简短：

- `independent_parallel`：理解为当前图是唯一目标，不把这条模式说明写进提示词。
- `anchor_consistency`：理解为当前图是目标；其他图只提供所选目标的身份或背景设计参考，不能传递构图、动作、物体或关系；不把这条模式说明写进提示词。

不得使用固定长开头或四大段模板。生成前自行计数整段提示词的 Unicode 字符数；超长必须重写，不能截断。检查提示词恰好两句、第一句确实只有唯一目标、第二句确实只有最危险关系和“其余内容不变”，并确认没有第二类编辑目标后，才写入 JSON。
