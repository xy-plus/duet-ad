# image-postprocess

## 目标

为了降低素材重复度，第一优先级是最终视频连续性和现实合理性：扭曲、元素突变、物理或接触关系异常一票否决；人物或背景替换仅是用于去重的第二优先级，只有通过第一层才评价。

本 Skill 只生成提示词，不编辑图片、不调用 Seedream；输出不表示编辑已执行、成功或被视频采用。

## 输入

只允许读取：

- `work/request.json`：`edit_mode` 只能是 `anchor_consistency` 或 `independent_parallel`；`segments` 按段号升序提供 `index`、`chain_id`、`join_mode`；短视频只有第 0 段，多段从 1 连续递增。
- `work/segments/<段号>/keyframes/01.png、02.png …`：对应片段的全部冻结关键帧。

不得读取视频、视频生成提示词、台词、音频、项目目录、其他路径或未列出的文件。

## 唯一输出

只写 `work/image_optimization.json`，不得写其他文件。输出必须是 UTF-8 JSON，结构严格如下：

```json
{"version":1,"segment_indices":[1,2],"global_elements":[{"id":"PERSON_01","kind":"person","source":"原特征","replacement":"统一新脸","segments":[1,2]}],"segment_prompts":[{"segment_index":1,"prompt":"真实提交给 Seedream 的提示词"},{"segment_index":2,"prompt":"真实提交给 Seedream 的提示词"}]}
```

- `segment_indices` 必须与请求段号完全一致；`segment_prompts` 覆盖全部段并按段号升序排列。
- 每段 `prompt` 非空、恰好两句，以整段 Unicode 字符数计不超过 140 个 Unicode 字符。
- 短视频的 `segment_indices` 是 `[0]`，`global_elements` 必须是空数组。
- 除规定字段外不得增加字段；不得用 Markdown 代码围栏包裹 JSON。

## 项目级安全决策

1. 先检查全项目全部关键帧；去重目标只能是 `人物外观` 或 `背景`。全项目构建跨段相关组件：连接同一 `chain_id`，或可见为同一人物、核心前景对象或互动关系的段；识别功能道具、商品、玩具或人与物互动，不得从不可见信息推断关联。
2. 每个组件只做一次策略选择并冻结，不得逐段摇摆。逐帧检查手与功能道具或玩具的握持、插接、对齐、接触和遮挡；任一相关段存在手—功能道具/玩具的高风险关系，整个组件统一选择背景路线，也就是整个相关组件统一只替换背景。人物和服装不得变化，全部前景对象、像素语义和关系保持不变。
3. 背景路线只选一个在全部相关段稳定可见、面积尽量大的安全背景表面类别，优先地面，其次墙面；不得映射全部背景或组合表面。可按灰石墙、原有砖墙、木格栅、地板等跨帧稳定背景表面类别识别，每个组件只冻结一个。
4. 对该表面做原位材质映射：改为同功能、同表面类别但明显不同的材质或色调；保留原表面的边界、分块/拼缝、方向、透视和接触几何，保持光线方向。冻结同一个新设计和 `SCENE replacement`，在所有相关段逐字复用。墙体、门窗、插座、踢脚线、墙地交界的建筑几何与位置不变；固定构件、家具、陈设不得新增、删除或移动；不得描述或生成新房间。
5. 只有组件无上述高风险关系、找不到稳定安全背景表面，同一人物可确认且人物在所有相关段都稳定清晰，替换不降低连续性和现实合理性时，才可为整个组件统一选择人物路线。只替换同一人物的新脸，即只换脸，不换服装；保持可见的性别呈现、肤色和整体风格、年龄和气质，新脸长相略有不同，不得推断身份或具体族裔。锁定头部位置、大小、朝向、裁切和遮挡；跨段 `PERSON replacement` 必须在所有相关段逐字复用，满足时才允许项目级统一人物替换。
6. 不要求“全项目完全没有核心前景互动”，只判断当前组件。高风险组件找不到合格表面时放弃去重，不得退到人物路线；输出两句不改动提示词，不为未替换元素建立 `global_elements`。画质、功能道具、玩具、商品、宠物不得作为差异化目标；没有人物时不得新增人物。

## 不可编辑内容

- 核心商品、功能道具、玩具、手部，以及人与物/物与物的握持、接触、插入、对齐、连接、遮挡、前后顺序、数量、结构、方向，全部不可编辑；不得同类改款。
- 保持目标帧自身的画幅、裁切、机位、镜头、透视、景别、构图、光线、焦点、景深、人物与动物数量、姿态、动作、视线，以及非目标元素的位置、比例和可见部分。
- 提示词只点名目标帧中最容易误改的剧情核心物体和关系，不复述全部构图或叙事；不描述视频过程、运镜、转场、台词或音频。
- 禁止恢复或新增字幕、文字、Logo、水印、贴纸、界面元素、品牌标识或乱码。

## 跨段一致性

1. `global_elements` 的 schema 只允许 `PERSON`、`OUTFIT`、`SCENE`；PROP、PRODUCT、SUBJECT 不得建立新映射。只收录实际跨段替换且跨至少两段重复的 PERSON 或 SCENE；本策略不换服装，因此不得输出 `OUTFIT`；单段元素和仅被保持的元素不进入。
2. 人物使用 `PERSON/person`，背景使用 `SCENE/scene`；同类 ID 从 `01` 连续编号，数组按完整 `id` 的字典序输出。
3. `source` 只写原目标的稳定可见特征；`replacement` 只写可复用的新身份或设计，不写构图、动作、光线、位置或关系。
4. `segments` 只列实际执行替换的段号，升序、去重且至少两段。每个背景组件只为选中的一个表面类别建立 `SCENE`，所有相关段逐字复用同一个材质或色调及 `SCENE replacement`；人物路线同样逐字复用 `PERSON replacement`。
5. 同一 `chain_id` 的 `continue` 段优先视为连续画面；`hard_cut` 不自动代表人物或场景变化，仍按可见证据判断。

## 每段 Seedream 提示词

每段全部关键帧共享一份提交给 Seedream 的提示词，不含 Markdown、解释或分析；恰好两句，整段不超过 140 个 Unicode 字符，按组件冻结的唯一路线写。

### 背景路线

1. 第一句表达原位表面替换：只将所选的一类墙、地面或固定建筑表面改为冻结的材质或色调，保留原表面的边界、分块/拼缝、方向、透视和接触几何，并保持光线方向。若某帧目标表面不可见，同句明确该帧不做其他改变。不得描述新房间，不得用“游戏角”“展示区”等词诱导新增陈设，不得要求人物重绘或服装变化。
2. 第二句保护全部前景像素语义：固定构件、家具、陈设不得新增、删除或移动；人物、服装、手、玩具、商品及其握持、插接、对齐、遮挡关系全不变，并禁止增删文字或 Logo。不得省略这些保护，也不得写全景复述、物体清单、画质美化、真实摄影增强或其他编辑目标。

### 人物路线

1. 第一句只替换同一人物的新脸；保持可见的性别呈现、肤色和整体风格、年龄和气质，锁定头部位置、大小、朝向、裁切和遮挡。只换脸，不换服装、背景或身体其他部分。
2. 第二句明确固定构件、家具、陈设不得新增、删除或移动；人物除脸外、服装、手、玩具、商品及其握持、插接、对齐、遮挡关系全不变，并禁止增删文字或 Logo。

模式约束必须压入第二句，不得增加第三句：`independent_parallel` 无需写“当前图是唯一目标”，且不得写参考人物、参考角色或其他图；`anchor_consistency` 必须说明其他图只提供目标设计（冻结的表面材质/色调或新脸），不传递人物、构图、动作、物体或关系。

不得使用固定长开头或额外句子。生成前自行计数整段提示词的 Unicode 字符数；超长必须重写，不能截断。通过以上约束后才写入 JSON。
