# image-postprocess

## 目标

为了降低素材重复度，在关键帧进入视频生成前，为可能执行的 Seedream 二次编辑生成提示词。每段只替换一个主要目标，其余画面内容和关系保持不变；同一替换目标跨段出现时复用同一个新设计。

本 Skill 只生成提示词，不编辑图片、不调用 Seedream。生成提示词不代表图片二次编辑一定执行、成功或被视频生成采用。

## 输入

只允许读取：

- `work/request.json`：
  - `edit_mode` 只能是 `anchor_consistency` 或 `independent_parallel`。
  - `segments` 按段号升序提供 `index`、`chain_id`、`join_mode`。
  - 短视频只有第 0 段；多段视频的段号从 1 连续递增。
- `work/segments/<段号>/keyframes/01.png、02.png …`：对应片段的全部冻结关键帧。

不得读取视频、视频生成提示词、台词、音频、项目目录、其他路径或未列出的文件。

## 唯一输出

只写 `work/image_optimization.json`，不得写其他文件。输出必须是 UTF-8 JSON，结构严格如下：

```json
{
  "version": 1,
  "segment_indices": [1, 2],
  "global_elements": [
    {
      "id": "PERSON_01",
      "kind": "person",
      "source": "跨段重复出现的原人物可见特征",
      "replacement": "统一的新人物身份和可复用外观特征",
      "segments": [1, 2]
    }
  ],
  "segment_prompts": [
    {
      "segment_index": 1,
      "prompt": "本段真实提交给 Seedream 的完整提示词"
    },
    {
      "segment_index": 2,
      "prompt": "本段真实提交给 Seedream 的完整提示词"
    }
  ]
}
```

- `segment_indices` 必须与请求段号完全一致。
- `segment_prompts` 必须覆盖全部段并按段号升序排列；每段提示词非空，以 Unicode 字符数计不超过 220 个字符。
- 短视频的 `segment_indices` 是 `[0]`，`global_elements` 必须是空数组。
- 除规定字段外不得增加字段；不得用 Markdown 代码围栏包裹 JSON。

## 单一目标选择

1. 先检查全部片段及其关键帧，再为每段只选择一个主要编辑目标，严格二选一：`人物外观`或`背景`。
2. 先判断是否存在手持、握持、插入、安装、发射、对齐、连接、遮挡等高风险人-物或物-物互动。存在时唯一选择背景，即使人物稳定可见；选择背景时人物、服装、手部、全部前景物及其关系均不得改变。
3. 只有没有高风险互动，且多帧中人物脸部和服装足够可见、能够建立稳定同一性时，才选择人物外观；否则选择背景。选择人物外观时不得修改背景。
4. `人物外观`指一个人物的新面孔；可连同同色、同用途、同风格但不同款的服装一起设计，并仍视为同一个人物替换目标。新人物保持可见的性别呈现、相近年龄和整体气质，长相略有不同；不推断身份或具体族裔。
5. 背景替换保持场景类别与功能、原透视、光向和地面与人物的接触边界，只设计同类型但不重复的、真实的同类环境；不得借背景替换改动前景主体、核心物体或关系。
6. 画质、功能道具、玩具、商品、宠物不得作为差异化目标。功能道具、玩具、商品不得被修改，也不得同类改款。不得在同一段同时替换人物外观和背景，也不得增加第二个替换目标。
7. 没有人物时不得新增人物；不可见的信息不得推断或虚构。

## 不可编辑内容

- 核心商品、功能道具、玩具、手部，以及人与物/物与物的握持、接触、插入、对齐、连接、遮挡、前后顺序、数量、结构、方向，全部不可编辑；不得同类改款。
- 保持目标帧自身的画幅、裁切、机位、镜头、透视、景别、构图、光线、焦点、景深、人物与动物数量、姿态、动作、视线，以及非目标元素的位置、比例和可见部分。
- 提示词只点名目标帧中最容易误改的剧情核心物体和关系，不复述全部构图或叙事，不描述视频过程、运镜、转场、台词或音频。
- 禁止恢复或新增字幕、文字、Logo、水印、贴纸、界面元素、品牌标识或乱码。

## 跨段一致性

1. 跨段映射只允许 PERSON、OUTFIT、SCENE。只有真正被替换且跨段重复的 PERSON、OUTFIT、SCENE 才进入 `global_elements`；PROP、PRODUCT、SUBJECT 不得建立新映射。只出现于一段或仅被保持的元素不进入 `global_elements`。
2. 若同一人物跨段出现且任一相关段存在高风险互动，相关各段统一选择背景并保持该人物原样，不得只在部分段替换该人物。同一重复背景若在多个相关段均被替换，必须使用同一个 SCENE 映射，SCENE replacement 逐字复用。
3. 人物使用 `PERSON/person`，人物目标中一并替换的服装使用 `OUTFIT/outfit`，背景使用 `SCENE/scene`。同类 ID 从 `01` 连续编号，按 ID 升序输出。
4. `source` 只写识别原目标所需的稳定可见特征；`replacement` 只写可直接复用的新身份或新设计，不写构图、动作、光线、位置或关系。
5. `segments` 只列实际执行该替换的段号，升序、去重且至少包含两段。相同替换描述必须跨段逐字复用。
6. 同一 `chain_id` 的 `continue` 段优先视为连续画面；`hard_cut` 不自动代表人物或场景变化，仍以可见证据判断。以上规则适用于任何项目，不得硬编码当前项目的人物、道具或场景。

## 每段 Seedream 提示词

每段所有关键帧共享一份可直接提交给 Seedream 的提示词，不得包含 Markdown、解释或分析。整段只写三个短句：

1. 第一短句直接写唯一替换目标及具体新设计；人物目标可在同一句包含其配套服装，背景目标不得包含人物变化。
2. 第二句只锁最危险的对象或关系；不复述其他构图、动作或叙事。
3. 第三句只写极简禁止项；不得写画质优化、摄影质量或风格增强。

模式说明保持简短：

- `independent_parallel`：在第一句末尾极简说明当前图是唯一目标。
- `anchor_consistency`：在第一句末尾极简说明当前图是目标；其他图只提供所选目标的身份或背景设计参考，不能传递构图、动作、物体或关系。

不得使用固定开头，不得复述全场景，不得使用四大段模板。生成前自行计数整段提示词的 Unicode 字符数；超长必须重写，不能截断。检查第一句确实是唯一目标、没有第二类编辑目标，并确认所有不可编辑内容与关系均未被要求改变后，才写入 JSON。
