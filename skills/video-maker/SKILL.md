# video-maker

## 单一职责

只分析原视频。项目统一表示为 `segments[N>=1]`；N=1 与 N>1 使用同一规则。后端把每个 segment 放入独立工作目录；逐 segment 阶段只处理当前目录，不跨目录取帧或补叙事。为减少分析耗时，后端可把原始关键帧确定性缩小约一半后放入分析沙箱；帧编号、顺序和源时间语义不变，原始全分辨率帧仍由后端冻结并供后续节点使用。全部 segment 原功能完成后，后端可在隔离目录以 `phase="project_index"` 额外调用本 Skill 一次；该阶段只读同一规则生成的全项目分析关键帧，不改变逐 segment 阶段的任何既有输出或后续原图合同。

当前 segment 完成三件事：

1. 做关键词和片段分析，理清可见主体、场景、对象、动作、镜头、转场和因果。
2. 从预抽取帧中选择每段恰好 9 张原始关键帧。
3. 根据原始帧编写旧视频提示词。

不要执行图片优化、内容替换或最终提示词融合；逐 segment 不产生额外计划、绑定或分类产物；`project_index` 只增加下文的源元素索引。

## 输入与输出

所有路径相对当前工作目录。输入位于 `work/`：

- `work/NN_frame_*.png`：外部程序按源时间抽取的原始帧，关键帧唯一来源。
- `work/contact_sheet_*.jpg`：分页联系表，仅用于导航和总览。
- `work/manifest.json`：当前 segment 的时长、尺寸、帧率和帧数。
- `work/scenes.json`：可选场景边界辅助信息；与原始帧冲突时以原始帧为准。

逐 segment 输出只有 `work/keyframes/01.png` 至 `09.png` 和 `work/prompt.txt`；`project_index` 的输入与输出单独遵循下文，不读写上述逐段产物。

## 关键词与片段分析

1. 查看全部联系表，必要时打开对应原始帧确认细节。
2. 提取主体、场景、关键对象、核心动作、结果、镜头尺度、机位、运动、构图和转场关键词。
3. 按源时间理清初始状态 → 动作推进 → 结果状态；每个结果有已观察原因，每个转场能定位到帧。
4. 关键词分析只用于选帧和编写提示词，不另写关键词、分段或其他产物。

眼见为实：不得从字幕、画面文字、文件名或常识补造不可见事实；辅助信息与像素冲突时以已查看原始帧为准。

## 选择 9 张原始关键帧

1. 先确认当前 segment 至少有 9 张不同且可读的原始帧；不足时说明输入不足，不得重复同一帧凑足 9 张。
2. 恰好选择 9 张不同的原始帧，覆盖开场、主要动作、必要转场和结果；不得减少数量。
3. 按源时间升序；每帧承担一个主导状态，连续帧避免完全相同状态。
4. 将所选源文件逐字节复制为 `work/keyframes/01.png` 至 `09.png`，连续无缺号。
5. 不得裁剪、调色、修图、重绘或生成替代帧。

## 编写旧视频提示词

只依据已查看原始帧写 `work/prompt.txt`，忠实保留动作、镜头、构图、节奏和 segment 时间轴；不引入优化后的图片内容、替换内容或新设计。使用用户语言，覆盖以下骨架：

```text
生成一支与源片段时长一致、采用源视频[比例]、[分辨率，默认 720p]的[旧视频主题]短视频。
关键词：[主体、场景、对象、动作与结果]。
镜头与构图：[镜头尺度、机位、运动、主体位置、视线与空间关系]。无字幕、贴纸或水印等叠加元素。
叙事：从图片1的初始状态开始，[按图片顺序描述动作和转场]；最后到达图片9的结果状态。
节奏与 segment 时间轴：[开场、推进、转场和收尾的相对节奏]。与源片段时长一致，不写具体秒数。
因果：[先看到动作，再看到变化；动作到哪里，变化到哪里；未受作用的内容保持原样。]
```

每个细节必须对应至少一张已查看原始帧。原子发布 `prompt.txt` 前检查图片编号、叙事顺序和引用严格一致。

## 项目级可替换元素索引

仅当 `work/project_index_request.json` 明确声明 `phase="project_index"` 时执行本阶段，且每个项目只执行一次。在所有 segment 的逐段视觉分析、9 张原始关键帧选择和旧视频提示词生成后增量补充；只读所有 segment 的半尺寸分析副本，不改变冻结原图、逐 segment 输出或后续节点。

请求只含冻结帧，形如：

```json
{"phase":"project_index","segments":[{"segment_index":1,"frames":[{"frame_order":1,"path":"work/segments/1/keyframes/01.png","sha256":"调用方冻结的分析副本字节哈希"}]}]}
```

严格按 `segments` 和 `frames` 顺序查看全部冻结帧。project_index 不读取 `work/prompt.txt`，也不从字幕、文件名、常识或片段提示词补造事实。

按 segment 顺序逐帧建立可见元素清单，全部 segment 检查完后再合并 ID 并写 JSON；不得只输出首个 segment 或只输出画面主体。逐帧回查每个 segment，确认已辨认的人物、实体和场景 occurrence 均保留。

汇总全视频中可能在后续图片处理中被替换的人物、持久非人物实体和场景；清晰、可独立替换的同类对象逐一列出，不用集合代替实例。非人物实体优先限于前景、被持握或被动作直接作用的独立对象，或跨至少两帧清晰可辨者；运动模糊、远景背景、过渡扫到的家具/收纳物/陈设/杂物不升格为实体，归入 scene。

### 跨帧证据与不可变索引 key

stable key 是跨帧绑定用的 ID；为同一元素建立稳定语义 key，不是外观摘要。先在每一帧标记直接可见候选，再以身份、形态或结构跨帧合并；物理上独立、可分别移动或分别接触的同类元素分别分配 ID，不用集合或群组 ID；无法确认不猜测合并。服装颜色、位置、动作或相邻关系不能单独定性。

遇到硬切、运动模糊、遮挡、纯色块、倒影或残影时重新判断，不传播前后 key；单独的手、衣角、头发或颜色块不新建人物/实体，也不把碎片升格为完整元素。occurrence 只覆盖当前帧像素能证实的元素；外观变化但身份特征相符仍复用 key。

逐帧回查已建 ID：跨 segment 或硬切后仍可辨认的同一人物、实体逐字复用原 ID；换 scene 不会清除可见人物或实体的 occurrence。单帧出镜只有在对象清晰、完整且位于前景、被持握或被动作直接作用时才记录。不因间隔漏记；硬切后先按新 scene 判断，只有背景结构、布局和光照直接连续时才复用 scene key。仅在画面显示且无法与既有 ID 确认时新增。

按每类元素首次确认的 `(segment_index, frame_order)` 顺序分别使用 `person-01`、`entity-01`、`scene-01` 这类中性编号；同一帧仅在画面可直接区分时按空间顺序编号，编号一经使用不重排。key 本身不得包含或暗示可替换的源属性（颜色、服装、材质、发型、道具、地点、动作、文字、语言）；这些写入 `source_visual_description`，可改动内容写入 `replaceable`，必须保持的身份、结构、关系和连续性写入 `preserve`。

只写 `work/element_index.json`，顶层精确为 `people/entities/scenes`；三类条目均使用 `source_visual_description`、`occurrences`、`replaceable`、`preserve`，每条 occurrence 使用 `segment_index` 与 `frame_orders`：

```json
{
  "people": {"person-01": {"source_visual_description":"源帧直接可见的稳定视觉特征","occurrences":[{"segment_index":1,"frame_orders":[1,2]}],"replaceable":["后续允许替换的可见属性"],"preserve":["身份、形态、关系或连续性"]}},
  "entities": {"entity-01": {"source_visual_description":"持久非人物实体的直接可见外观","occurrences":[{"segment_index":1,"frame_orders":[3]}],"replaceable":["后续允许替换的可见属性"],"preserve":["实体归属、形态或接触关系"]}},
  "scenes": {"scene-01": {"source_visual_description":"源环境语义、布局和直接可见结构","occurrences":[{"segment_index":1,"frame_orders":[1,2,3]}],"replaceable":["后续允许替换的环境属性"],"preserve":["构图、机位、空间关系、光色或环境连续性"]}}
}
```

`occurrences` 按 segment 和帧序升序且不重复，只记录元素直接可见帧；无对象时对应类别为空对象。`replaceable` 只写可换内容，`preserve` 只写替换后仍须一致内容。该文件直接作为 `image-postprocess` 的 `element_index` 输入；不要生成替换设计、参考图、图片提示词或其他文件。

每个阶段的声明产物都是最后动作：先写同目录临时文件，完整后原子替换最终文件；替换成功后立即退出。`project_index` 的提交标记为 `work/element_index.json`；逐段提交标记为最后写入的 `work/prompt.txt`，此前 9 张关键帧必须已发布。
