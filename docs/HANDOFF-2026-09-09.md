## 1. 项目是什么

视频改编服务：用户上传一段带货/口播视频 + 一张替换参考图，系统自动完成：

- 分段后用 H3 Max r2v（Picsart 供应商）逐段重生成：替换指定物品、替换人脸、更换背景、去字幕/去 logo；
- 台词三种模式：自动改写（可换语种）、保持原台词、**按描述生成口播**（用户提供 brief，DeepSeek 生成台词+时间线）；
- 音频链（v7）：IndexTTS2 预生成整轨台词 → 按段切片喂 H3 对口型 → 终剪用整轨 TTS 覆盖 H3 自带音频；
- 输出成片，按原视频时长计费（60 积分/秒，对外 API）。

## 3. 链路架构（release 当前版）

```
源视频 → 消字幕/去logo（MediaKit，可开关）→ 场景分段 → 4fps 抽帧
  → video-maker（DeepSeek，逐段 9 张半分辨率关键帧 → 段 visual_prompt）
  → whisper ASR → 台词节点（改写/保持/生成，DeepSeek + 时间线）
  → 全局元素索引（DeepSeek，人脸占比/替换对象判定）
  → 替换图版（Seedream，含人脸特写 tiles）
  → 人脸+头发灰块遮盖（YuNet 检测，灰块=致命遮盖，不用马赛克）
  → fusion（DeepSeek/Codex 可切，生成每段 H3 提示词；skill: skills/h3-max-r2v-prompt）
  → H3 Max r2v 逐段并行提交（Picsart）
  → 拼接 + IndexTTS2 整轨覆盖音频 → 成片
```

每段 H3 输入：预处理后段视频（消音+消字+灰块）+ 替换参考图 + 该段台词切片 + 最终提示词。最终提示词头部依次可含：灰块说明（该段实际打码时）→ 动作指令（有 adaptation_prompt 时）→ face replacement 块 → fusion 输出。

## 5. 总体改编提示词 AB 实验结论（重要，勿重复踩坑）

四组变体、同一输入四单（梳狗毛/项链保持/漱口水/项链口播）、同一提示词：

| 变体 | 注入方式 | h3_prompt 覆盖率 | 画面生效 |
|---|---|---|---|
| A（ab/adapt-videomaker @2c23b52） | 仅 VideoMaker | 0/15 | 0/4（Fusion 把改编意图当偏离过滤，其 authoritative_constraints 含 preserve scene/lighting） |
| B（ab/adapt-fusion @7166b28） | 仅 Fusion 字段+skill | 13/15 | 4/4 部分（多为局部元素） |
| A'（ab/adapt-videomaker @797312c） | 双注入 | 12/15 | 3/4，含唯一全片生效单 |
| A''（ab/adapt-vm-aware @39e4a2f） | VM + Fusion 仅 skill 感知 | 15/15 | 1/4 部分 |

第二轮语义强度实验（release 6872da1）：弱语义 neon 2/4 部分生效；强语义"整片换海上游艇" **0/4**。

**结论**：H3 r2v 模式只接受叠加式改动（加灯光/元素），不执行场景级替换。瓶颈在 H3 生成端而非提示词。产品引导应把该功能定位为"加元素/调氛围"。若未来要场景级改编，需换路径（改编段走图生视频），未做。

## 6. 其他关键实验结论

- **闪烁根因**（`data-verify/analysis/flicker-report.md`，1fe964f）：不是灰块漏脸（逐帧验证 true_leaks=0），是 ①YuNet 把手误检成脸→手持物被间歇误盖 ②狗单"时换时不换"是分镜级绑定问题（正脸换/背身不换）③段首 1-6 帧脸半出画漏检。灰块注入说明（ms/grayblock-explainer）已解决"灰块被 H3 画进成片"问题。
- **灰块必须盖全脸+头发+下巴**（faa63a5、baecbd5），否则 H3 能还原原脸。
- AutoDL 动作迁移链已废弃删除（164a662）；443 边缘 Caddy 的 release 资产路由落盘未 reload（需 sudo，暂不需要）。
