# 认证媒体与关键帧后处理

## 规则

| 当 | 则 |
| --- | --- |
| 页面需要源视频、成片、关键帧或后处理图片 | 使用 Bearer 请求文件 Blob，再生成当前会话专属 Object URL |
| 用户切换会话、资源变化、退出或组件卸载 | 撤销旧 Object URL，不能把前一登录会话的媒体继续显示给下一会话 |
| 媒体请求加载、失败或返回空 | 分别显示 loading、明确错误或空状态；不伪造播放器、图片和元数据 |
| 长视频详情可用 | 按服务端实际分段数展示时间、状态、首尾帧、其他关键帧、提示词和台词 |
| 会话允许后处理且尚未提交 | 可选择移除文字/字幕、移除常见 Logo/图标，至少选择一项后才能开始 |
| 用户提交后处理 | 立即冻结选项并关闭 Modal，主页面显示非阻塞后台状态卡；切换会话不取消任务 |
| 服务端返回 `postprocess_options_locked` | 拉取并显示服务端冻结选项，不按本地草稿自动重发 |
| 后处理部分成功或失败 | 只用服务端冻结选项重试失败项；请求 pending 时禁止重复点击 |
| 后处理有成功图片 | 通过认证 Blob URL 展示并允许 AntD 图片预览；失败项保留独立错误 |

## 边界

- 唯一原生视觉控件是 `src/ui/video.tsx` 封装的 `<video controls>`；它只接收已认证 Blob URL。
- 后处理图片永远不是 H3 输入，前端不提供把它们回灌生成的入口。
- 已锁定选项不可改；重试不根据当前 checkbox 重新构造选项。
- `postprocess_enabled=false`、只读会话或已有后处理记录时不显示新的配置入口。

## 例子

- 输入：源视频加载成功后切换到另一会话 → 输出：旧 Object URL 被撤销，新会话重新携带 Bearer 获取媒体。
- 输入：选择两项后处理并提交，随后切换会话 → 输出：Modal 已关闭，任务继续；返回后状态卡展示服务端进度和冻结选项。
